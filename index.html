第 01 步 / 專案與管理

先把專案管好，資料才能用得久。

整理課程資料時，先分清來源、工作檔與成果，再訂好檢查與更新方式。資料品質才有依據，下一次使用也不必從頭整理。目標是減少使用者重複交代與 AI 重做；總 Token 不保證下降。

學完後，你能建立資料位置與管理規則，並留下下一輪可接續的進度。先看模擬，再完成第 09 頁練習。
開始前：我的電腦準備好了嗎？

網頁模擬不需要安裝。真正操作時，需先安裝 Claude Code、完成登入並安裝 project-kickoff Skill。請由授課者協助首次設定。

Mac 開啟「終端機」；Windows 開啟已配置的終端機。一般終端機先輸入 claude --version 確認工具可用；找不到指令時先完成安裝。/project-kickoff 要在 Claude Code 對話內輸入。

本教材以活動月報為主案例；課程資料對話是將同一管理方法用於教學的遷移範例。

好的管理架構，讓資料品質可檢查、資料可持續維護。

專案定義要完成什麼；管理保存可信資料、規則與工作狀態。有效的資料架構、品質檢查與歸檔，能減少不必要的讀取與修正。資料更新後也要維護索引、版本與進度，下一輪才接得上。

這不是「每輪固定浪費一個 Token」。必要資料仍需讀取；快取是否沿用取決於內容、期限及平台。不能把新對話、子代理或重新開啟程式，一律視為全部重新計算。官方用量說明 · 快取說明。

為什麼要學會使用Terminal？

終端機是用文字指令操作電腦的介面。在本專案中，它讓你在選定的工作目錄啟動 Claude Code，使用 project-kickoff Skill，並核對助手建立的檔案。資料與規則可以直接留在專案中，供下一輪工作使用。

優點：操作能重複，成果能核對

  • 重複執行：將檢查與產圖步驟寫成程式，新資料到來時可沿用同一流程。
  • 減少手動切換：在同一工作目錄完成建檔、資料檢查、版本查看與助手對話。
  • 留下證據：檔案、執行輸出與版本差異可保存，方便追溯與交接。

缺點：需要理解位置、指令與權限

  • 學習門檻：需分辨一般終端機指令與 Claude Code 對話指令。
  • 操作可能影響檔案：位置或參數錯誤，可能改動不該改的內容；執行前先確認作用與路徑。
  • 環境有差異：工具須安裝，指令可能依作業系統不同；AI 建議與執行結果仍需核對。

終端機不會自動節省 Token。清楚的資料位置、可靠品質與最新工作狀態，有助於減少重複交代與重做；保存與讀取規則也會增加 Token。圖形介面仍適合瀏覽及編輯，兩種介面可以搭配。

我的 project-kickoff Skill 目的是什麼？

降低新手使用終端機建立專案的門檻，透過逐題問答與 AI Agent，產生有秩序、可維護、可接續的配置。使用者先提出目的，Skill 分次補問需求，提出資料夾、版本與 Context 方案，再將已確認答案寫成 README.md、CLAUDE.md、PROGRESS.md 等配置。

這個實作專案要改善的是開工與交接流程：減少新手自行猜配置、反覆說明規則，以及下一輪重新找資料的工作。建檔後仍須檢查資料品質、保存證據並持續更新；Skill 不保證資料正確，也不取代成果驗證。

第 02 步 / Skill 架構與流程

從一個目的，到可接續的專案配置

project-kickoff 是給 AI Agent 的工作指引。Claude Code 載入 Skill 後，依需要讀參考及範本，在工具與授權允許的範圍內建檔。

簡單開始：三個核心問題

要做什麼？→資料在哪裡？→怎樣算完成？

助手一次問一題，已知答案跳過。不知道就說「請幫我建議」。接著由助手提出資料夾、品質、版本與交接方案，只補問影響下一步的決策。

第 03 步 / Token 與浪費

沒有維護，AI 就得反覆找、問、改。

Token 是模型處理文字的單位。Context 是本次可使用的規則、對話與資料。專案沒有維護時，助手可能讀到過期版本、缺少檢查證據，還要反覆追問。對話變長，工作狀態卻仍不清楚。

Context 難以接續

決策只留在聊天裡，進度沒有更新。新對話不知道做到哪裡，舊對話又混著過期說明，容易重問或重做。

資料結果不穩定

來源、欄位與版本沒有固定約定。不同檔案可能算出不同結果；沒有驗證紀錄，就難以判斷哪個可信。

時間與 Token 浪費

多讀幾份舊檔、多問幾輪背景，再修正錯誤與重產圖。這些往返都可能增加處理時間與模型用量。

版本不明→重找與重讀→發現錯誤→重問與重做→Context 更雜

實測告訴我們什麼？
本專案單一情境測試中，完整交接的總 Token 比無交接多 7.6%，部分交接多 19.4%；完整交接使使用者當場補充的事實由 5 項降至 1 項，並避免重踩已記錄的權限問題。
歷史按需讀取測試通知另記 88,513 tokens，對照既有基準 83,976，增加約 5.4%；額外驗證與輸出也不同，不能把差異歸因於規則。這是特定測試與平台計數口徑下的結果，不代表所有專案。本頁時間與 Token 模擬是假設，不能作為實測節約證據。可支持的效益是減少重複交代與重做，不是保證省 Token。

# 活動月報資料規則（教學示例）

## 來源與用途

資料是本頁五列模擬活動資料，不是真實活動紀錄。
來源原檔保留；工作資料另存，實際專案路徑依授權確認。

## 檢查條件

- 活動 ID 不得空白。是否必須唯一，要依資料用途確認。
- 本例每個活動應有一列；重複 ID 先查原因，不直接刪除。
- 報名數應為非負整數；文字或異常值先核對來源，不猜值。
- 核對必要欄位、缺值、單位與日期定義；未執行的檢查不標通過。

## 本例已確認的修正

1. A02 重複列是重送：保留一列，移除工作資料中的重送列。
2. A04「三十」經示例來源確認為 30：只在工作資料轉為數值。
3. 核對四個唯一活動，報名次數合計 108。不是去重人數。

以上依據由教材預先設定。真實資料必須重新核對，不能為得到 108 而改資料。
網頁按鈕只改示範畫面，不會修改電腦上的檔案。

## 修正與檢查證據

記錄來源版本、問題、確認依據、實際動作、受影響筆數、輸出位置及檢查結果。
保存重跑方法；個資與敏感內容不得寫入公開日誌。
修正後重跑檢查，仍失敗就記下阻礙，不標為完成。

## 更新與接續

更新 README 的資料與成果索引，PROGRESS 記錄驗證、待辦及下一步。
下一批資料到來，先確認欄位及規則是否改變，再重新檢查。
建立規則檔不等於完成資料驗證、歸檔或備份。

命名讓版本可辨識

第 08 步 / Context 與交接
Context 管理：按需讀取，保存再接續
現在有清楚位置、可靠資料與最新狀態。助手才能只讀這一步需要的內容，並在長任務中保存交接。
減少不必要讀取：三個工作規則
  1. 按需讀取：同一對話中未變更的內容沿用；新對話或壓縮後仍核對必要規則與進度。
  2. 限定搜尋：先依索引找路徑，再查相關資料夾與段落；找不到才擴大。
  3. 局部更新：先看錯誤與差異，只更新受影響內容，核對跨檔一致性。
來源限制、必要原文、驗證證據與操作狀態不能省略。是否降低總 Token，仍需實測。
減少輸入與輸出浪費
先讀README與PROGRESS，再讀必要來源。搜尋限定範圍。長工具輸出存檔，對話保留結論、路徑與下一步。
保留可以接續的內容
目標、禁止事項、決策、必要路徑與 ID、驗證、未解錯誤及下一步。逐字要求的內容存原檔，摘要只記位置。
互動：此刻該繼續，還是準備交接？
加入規則後，助手會怎麼提醒？
先選主動或被動操作，再按 ▶。同一個階段，看看是誰先提出保存與交接。
主動：助手依規則提醒
工作中發現長輸出、新決策或階段完成，就提出保存與接續指示，繼續已授權工作。
被動：使用者先提出問題
使用者詢問「需要保存嗎？」或「可以重開嗎？」後，助手核對狀態並說明下一步。
主動是助手執行任務時依規則判斷；不是關閉對話後仍在背景監控。實際是否提醒，取決於工具可見狀態與規則是否被遵循。
● ● ● Claude Code · Context 規則教學模擬
預先編寫的情境模擬，不是即時 AI。實際提醒須由助手讀取並遵循規則；不保證固定彈窗，也不會自動執行 /compact 或修改檔案。
保存不等於壓縮。Skill 提供規則與提醒，不會改變模型容量或系統壓縮門檻。提醒後繼續已授權工作。
