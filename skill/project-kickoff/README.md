# Project Kickoff

用一次一題的問答，將專案需求整理成資料夾、規則與進度檔。你不必先懂終端機指令、設計完整資料架構，或寫一長串 prompt。

**先建立好的管理架構，資料品質才有檢查依據，也才能持續更新與維護。** 保存來源、版本、驗證與下一步，可以減少 AI 重複搜尋及修正；實際 Token 節約量仍待量測。

## 適合哪些工作？

- 新建課程教材、研究分析、網站或工具專案。
- 接手缺少說明、規則與進度紀錄的專案。
- 需求改變後，重新確認範圍與初始配置。

一般修改、單一檔案任務或純指令查詢，不必重新跑完整開工訪談。

## 安裝到 Claude Code

1. 從 [GitHub 儲存庫](https://github.com/ganma0517/project-kickoff) 選擇 **Code → Download ZIP**，再解壓。
2. 取出完整 `skill/project-kickoff/` 資料夾。
3. 放入下列其中一個位置：

| 使用範圍 | 完整路徑 |
| --- | --- |
| 個人使用，跨專案可用 | `~/.claude/skills/project-kickoff/` |
| 只在指定專案使用 | `<專案根目錄>/.claude/skills/project-kickoff/` |

保留 `SKILL.md`、`references/` 與 `assets/`，不要只複製主檔。已有同名版本時，先比較內容與自訂規則再更新。

安裝後，在選定工作目錄啟動 Claude Code。輸入 `/project-kickoff`；若找不到，核對安裝路徑後重新啟動工作階段。

[官方 Skills 安裝與使用說明](https://code.claude.com/docs/en/skills)。本儲存庫的 `.skill` 檔是 ZIP 封裝，可用解壓工具開啟，並非專用安裝指令。

## 開始使用

在 Claude Code 對話中輸入：

```text
/project-kickoff
```

以下是問答示例，不必一次貼入：

> 助手：這個專案要解決什麼問題？  
> 使用者：整理這學期的課程資料，供下學期沿用。  
> 助手：需要保留哪些成果？  
> 使用者：教材與作業成果；存放方式請幫我建議。

預設一次問一題。已有答案不重問；不知道怎麼選時，直接說「請幫我建議」。使用者要求加快時，可一次回答最多三題。

## Skill 如何工作？

```text
讀目前目錄與已知資訊
        ↓
逐題補問目的、資料、驗收、安排與位置
        ↓
建議必要資料夾、版本與 Context 工作方式
        ↓
整理配置摘要；未確認的必要決策先補問
        ↓
依已有授權建檔，核對實際結果
        ↓
保存進度、待確認事項與下一步
```

只建立需要的資料夾。已有專案沿用現有約定，不自行搬動全部檔案。已授權的例行建檔不反覆要求批准；需要使用者決定的事才補問。

## 產出什麼？

| 檔案 | 用途 |
| --- | --- |
| `README.md` | 專案目的、資料地圖、來源限制、使用與驗收方式 |
| `CLAUDE.md` | 長期規則、來源保護、Context 保存與接續方式 |
| `PROGRESS.md` | 真實狀態、驗證結果、待確認、未解問題與下一步 |
| 各資料夾的 `README.md` | 用途、適合檔案類型與限制 |
| `.gitignore`（使用 Git 時） | 不應納入版本的資料、暫存與備份等排除規則 |

資料夾依需求選用，例如：

| 位置 | 存放內容 |
| --- | --- |
| `data/` | 獲准的來源與工作資料，原始檔與清理後資料分開 |
| `materials/`、`ref/` | 教材、參考文獻與引用索引 |
| `src/`、`figures/` | 程式、圖表與圖形素材 |
| `out/`、`draft/` | 交付成果、檢查證據與草稿 |
| `backup/`、`_scratch/` | 獲准快照與暫存；備份和清理另依規則執行 |

建立 `data/` 不代表啟動資料庫服務；建立 `backup/` 不代表完成備份。建檔後仍須取得獲准資料、執行品質檢查與驗證成果。

## 換新對話如何接續？

請助手先讀 `README.md`、`CLAUDE.md` 與 `PROGRESS.md`，核對目前檔案及操作狀態，再執行下一步。不要假設所有說明檔都會自動載入。

新資料到來後，保存來源、檢查品質、重跑成果、驗證結果，再更新索引與進度。一般接續不必重新呼叫 Skill 訪談所有問題。

## 使用邊界

- 保留來源原檔；受限資料與個資先確認使用範圍，不自行公開、推送或寫入憑證。
- 未執行工作不得標為完成；計畫、骨架與成果驗證分開回報。
- 保存不等於壓縮。Skill 不安裝監控器、不修改模型容量或系統壓縮門檻。
- 60% 保存、75% 評估壓縮是可調整工作建議，不是官方門檻；用量未知就標示未知。
- 不能中斷的操作先保存狀態，到安全停點再評估換對話或壓縮。

## 教材與驗證

儲存庫根目錄的 `index.html` 與 `project-report-interactive.html` 可下載後離線開啟。終端機動畫與時間／Token 比較是教學模擬，不執行 AI 或電腦操作。

既有模擬案例通過 8 項本機檢查；單一交接檔恢復案例通過 8 項檢查，沒有直接觸發系統內部自動壓縮。最新逐題訪談規則、真人學習效果及實際 Token 節約仍待跨 AI 與使用者實測。
