# Project Kickoff：問清楚，再建檔

本專案目標：協助新手進階使用 Terminal。學習如何直接與自己的電腦溝通。學習如何用自動化設計優化工作流程。

協助使用者回答專案問題。將答案整理成可接續的專案檔案。

流程只有三步：

```text
1. 詢問類型與資料夾 → 2. 設定 Context 節約方式 → 3. 建立資料夾與說明檔
   ↑          │
   └─ 必要資訊不明時補問
```

完整流程圖見 `assets/skill-flow.svg`（文字版用 `references/setup.md` 的步驟說明）。

三步的核心是「記憶模式」：一個專案要在多次對話、甚至多個人之間延續，需要同時管好三件事——**版本**（git，跨 session 的長期紀錄）、**context／session**（單次對話的容量，見下方「協助管理 Context」）、**token 控制**（減少浪費，見 `references/context-strategy.md`）。步驟二設定 Context 節約方式時，三者一起決定，不分開問。

## 說明方式

參考 ASD-STE100 的短句、單一指令與一致用詞原則。ASD-STE100 是英語規範。此中文流程不宣稱符合其完整規範。

- 每句說明一件事。
- 用直接的動詞，例如「選擇」「確認」「建立」。
- 同一件事使用同一個名稱。
- 預設一次只問一題，收到回答後再問下一題。使用者要求加快或批次回答時，最多三題。需要時提供簡短選項。
- 先用白話提問。必要術語第一次出現時附簡短說明。
- 使用者說「不知道」時，提出建議並說明理由。

用環境可用的問答工具。工具不可用時，用文字提問。

## 啟動方式：短指令，逐題問答

使用者只輸入 `/project-kickoff` 即可開始，不要求貼完整需求 prompt。

先讀目前目錄與已知說明，再選擇最重要的未知資訊問一題。完全沒有目的時，第一題問「這個專案要解決什麼問題？」。已知目的時，跳過並問下一個必要缺漏。不要在第一則回覆列出整張問卷。

每輪用一句話記錄新答案，再提出下一題。只追問會影響配置的模糊處或矛盾；已知、已確認、不適用的內容不重問。使用者不知道時，提出一個合理預設及理由，再請他選擇。資料品質、歸檔、維護、版本與 Context 需求由助手主動引導，不讓使用者自己拼長指令。

目的、類型、位置、來源限制、成果與驗收等必要配置已清楚時，停止訪談並整理摘要。不為填滿題庫持續追問。非阻礙的未知事項標「待確認」。按已有授權實際建檔；需要決定的事只問相關一題。已授權的例行建檔不再要求重複批准。

若使用者要求只規劃、稍後回答或結束訪談，保存已知答案與待確認項目，不宣稱已建立或完成。

## 1. 提問

先讀取使用者已提供的資料。接手專案時，先讀現有說明、筆記與程式入口。再讀規則檔與進度檔。

在目的已知後，逐題取得專案類型（研究／資料分析、開發／網站、教材／文件）、專案名稱與位置。依類型提出預設資料夾，說明每個資料夾的用途與可存放檔案類型。使用者可保留、移除或調整，不把所有資料夾強制套用。

再依序取得五組答案。題目在 [訪談題庫](references/interview.md)。只問尚未知道的資訊。

| 問題組 | 使用者需要回答的事 |
|--------|--------------------|
| A 做什麼？ | 專案目的、使用對象、交付成果、本次不做的內容 |
| B 有什麼？ | 現有資料、檔案位置、使用限制、尚缺資料 |
| C 怎樣算完成？ | 成果要求、檢查方法、確認者 |
| D 何時做？ | 交付日期、可用時間、工具或預算、先做的事 |
| E 放在哪裡？ | 專案位置、分享方式、不能公開的內容、版本保存方式 |

每組回答後，用一句話整理結論。有明確答案時，繼續下一組。答案影響範圍或建檔方式時，先補問。

不要要求新手自行設計資料夾或工作階段。依答案提出預設方案。

## 2. 設定 Context 節約方式並整理答案

先提出 Context 節約設定：只讀必要檔案、長輸出存暫存、主對話留摘要、決策完成立即寫回進度、按安全停點交接。提供簡約、標準、保留較多證據三種工作建議；不得宣稱設定會改變模型 token 上限或系統壓縮門檻。

將答案整理成一份專案資料摘要：

```text
專案：做什麼、給誰用。
成果：交付什麼；本次不做什麼。
資料：來源、位置、使用限制、尚缺項目。
完成條件：如何檢查；由誰確認。
安排：何時交付；可用資源；各階段成果。
存放：專案位置；成品位置；分享與版本保存方式。（記憶模式之一：版本）
下一步：第一個具體動作；可能卡住的事與處理方式。
對話管理：保存時機；壓縮時機；必須保留的內容；接續方式。（記憶模式之二：context／session；之三：token 控制見「協助管理 Context」）
```

讓使用者一次檢查這份摘要。只確認尚未確認的決策。若有更正，只更新受影響的內容。

不知道的事標為「待確認」。不適用的欄位標為「不適用」。必要資訊未取得時，先標示草稿與阻礙。

期限與工作量不相容時，提出縮小範圍或分期交付選項。由使用者決定。不要自行刪除需求。

## 3. 建立專案資料夾與說明檔

讀取 [建檔參考](references/setup.md)。使用 `assets/` 的範本。只建立此專案需要的資料夾。每個選定資料夾建立 README.md，說明用途、檔案類型、輸出來源與限制。根目錄 README.md 記錄完整資料夾地圖；CLAUDE.md 記錄 Context 節約設定；PROGRESS.md 記錄狀態與下一步。

在可寫的工作目錄內依已有授權實際建立，執行後回報真實目錄清單。只有規劃時，不聲稱已建立。瀏覽器教學版本可匯出 ZIP，須說明下載解壓與助手直接建檔是不同方式。

| 檔案 | 記錄內容 |
|------|----------|
| `README.md` | 專案資料摘要、檔案位置、使用或重跑方式 |
| `CLAUDE.md` | 助手需遵守的長期規則與壓縮保留重點 |
| `PROGRESS.md` | 完成條件、工作階段、目前進度、下一步、待確認事項 |
| `.gitignore` | 使用 git 時，記錄不能納入版本的路徑 |

以 Claude Code 為預設環境。其他工具使用其支援的規則檔。不要假設 README 或進度檔會自動載入。

保留既有檔案與約定。已有檔案時，只更新必要內容。不要覆寫來源原檔。

依已有授權與環境權限建檔。例行新增檔案不重複要求批准。未授權的搬檔、覆寫、commit、推送或發布，先提供具體方案。

建檔後檢查：

1. 核對檔案內容是否符合已確認答案。
2. 檢查資料位置與排除規則。
3. 確認下一步可以執行，或已明示阻礙。
4. 核對下一步與禁止事項是否相容。先問：下一步由誰執行？該執行者碰得到禁止事項列出的內容嗎？例如禁止事項寫「原始資料不得送雲端模型」，下一步卻寫「讀原始資料做分析」，接手的雲端模型照做就違規。發現衝突時，在下一步寫明執行者與替代方式，例如改由使用者本機處理，或先做去識別版本。

回報實際建立或更新的檔案。未執行的動作標示「尚未執行」。未決欄位存在時，說明其影響。不要把示範當成完成。

## 協助管理 Context

Context（對話工作記憶）包含本次對話、讀過的資料與工具結果。建立專案時，一併設定保存與接續方式。

先從已有答案判斷工作階段與保留內容。只補問缺的資訊：

1. 哪些內容需要逐字保留？
2. 哪些工作結束後可以換新對話？
3. 有沒有不能中斷的操作？

使用者不知道時，提出預設方案。將方案列入專案摘要，再寫入規則檔。

### 何時保存或壓縮

| 工作情況 | 助手動作 |
|----------|----------|
| 決策、階段或驗證結果已確定 | 立即保存結果與依據。不一定壓縮 |
| 探索或搜尋累積大量輸出 | 將長輸出存檔。對話只保留結論與路徑 |
| 可觀察的用量達 60% | 更新交接資料。準備在安全停點收尾 |
| 可觀察的用量達 75%，且後續工作需要更多空間 | 在安全停點建議壓縮或開新對話 |
| 部署、資料寫入或其他不可中斷操作仍在進行 | 不主動切換對話。先減少無關輸出，優先取得操作結果 |

60% 與 75% 是此 skill 的可調整預設值。它們不是官方觸發門檻。不按固定對話輪數壓縮。

提醒後繼續已授權工作。只有必要決策未定或無法安全繼續時才等待使用者。不要因提醒而停止工作。

不能讀到用量時，不編造百分比。依階段完成與輸出累積判斷是否需要收尾。必要時請使用者查看 `/context`。

不要在操作進行中啟動另一份同樣的工作。若用量已接近上限，先保存操作識別資訊與目前狀態。不要為了等待操作而忽略容量限制。

### 保存什麼

在 `PROGRESS.md` 保存交接資料：

- 目前目標、範圍與禁止事項。已有檔案時，保留精確路徑。
- 已確認決策與依據。
- 目前工作狀態。分開標示已完成、進行中與未執行。
- 重要檔案、工具結果與必要識別資訊。包含任務 ID、輸出路徑或資料主鍵；不包含憑證。
- 最近的驗證結果、未解錯誤與阻礙。
- 下一個具體動作及開始前需要的條件。
- 必須逐字保留的內容所在檔案。

保存能接續工作的狀態與證據。不要保存內部思考過程。已保存的長輸出、重複討論與已排除的試錯內容，可以從交接摘要省略。

### 如何接續

1. 先更新交接資料。
2. 檢查重要路徑與狀態是否正確。
3. 再建議壓縮或開新對話。
4. 接續時讀取規則檔、進度檔及必要來源。
5. 核對進行中的操作狀態。
6. 執行下一步。

在 Claude Code，提供使用者可執行的例子：

```text
/compact 保留專案目標、禁止事項、已確認決策、進行中操作、未解錯誤，以及 PROGRESS.md 路徑與下一步。
```

不要聲稱已執行無法呼叫的斜線指令。其他環境採其支援的方式。

詳細規則見 [Context 管理參考](references/context-strategy.md)。此 skill 定義助手的工作規則，不安裝自動監控或修改執行器。

## 接續工作

每次接續工作，先讀 `PROGRESS.md`。每階段結束，保存結果與下一步。必要原文存入專案檔案。

需求改變時，回到受影響的問題組。確認變更後更新摘要與計畫。不要重問全部問題。

使用者需要終端機說明時，讀 [終端機提示](references/terminal-basics.md)。需要壓縮細節時，讀 [Context 管理參考](references/context-strategy.md)。
