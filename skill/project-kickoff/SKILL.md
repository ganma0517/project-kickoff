# Project Kickoff

協助新手把需求寫成有秩序、可維護、可接續的專案。以 Claude Code 為預設；其他工具採其支援的規則檔，不假設 README 或進度會自動載入。

## 1 釐清核心需求

使用者輸入 `/project-kickoff` 後，先讀現有目錄、說明與進度。從三個核心問題開始，只問未知的資訊：

- 要做什麼？確認目的與成果。
- 現有資料在哪裡？確認來源位置與使用限制。
- 怎樣算完成？確認可檢查的完成條件。

這是起點，不是固定三輪或一次三題。預設每次一題，收到回答後再問下一題。提問數以獨立決策計算。使用者要求批次時最多三題；只有版本、Context 與接續的整體方案可合併確認，不延伸為其他題組的綁題授權。

用白話短句及一致名稱。已知答案不重問；不知道時提出一個預設與理由。只補問會影響配置或下一步的決策，不為填滿題庫持續訪談。

依需要讀 [訪談題庫](references/interview.md)。題庫包含類型、名稱、位置、期限、分享等補問，並非必填清單。非阻礙的未知項目記錄最晚確認階段、受影響工作與延後可能增加的往返；阻礙下一步時先確認。

## 2 提出配置方案

依答案建議需要的資料夾、品質與維護規則、版本保存及 Context 方式。使用者不用自己拼長 prompt 或設計完整目錄。摘要包含目的、成果、來源限制、驗收、必要安排、資料地圖與下一步；只確認未決決策。

- 建檔與版本：讀 [建檔參考](references/setup.md)，使用適用範本。
- 整理資料：讀 [資料管理規則](references/data-management.md)，提供盤點索引、整理副本、品質清理、歸檔或助手建議的選項；已選定的不重問。
- Context：讀 [保存與交接規則](references/context-strategy.md)，設定按需讀取、長輸出保存、決策寫回及安全停點接續。
- 新手需操作說明時，讀 [終端機提示](references/terminal-basics.md)。

## 3 建檔與核對

依已有授權在可寫目錄建檔，只更新必要內容並保留既有約定。只規劃時保存摘要，不宣稱建檔完成。瀏覽器 ZIP 匯出與助手直接建檔是不同方式。

| 檔案 | 用途 |
|---|---|
| README.md | 目的、資料地圖、來源與使用方法 |
| CLAUDE.md 或平台規則檔 | 助手工作規則與交接保留內容 |
| PROGRESS.md | 完成條件、狀態、證據、待確認及下一步 |
| 各資料夾 README.md | 用途、檔案類型與限制 |
| DATA_RULES.md 或既有品質規則 | 涉及資料時的檢查及修正依據 |
| .gitignore | 使用 Git 時的排除規則 |

建檔後核對五件事：答案與檔案相符；資料位置及排除規則正確；下一步可執行或阻礙已明示；執行者及下一步符合禁止事項；跨檔的數量、路徑、用途、命名與版本一致。詳細例子見建檔參考。

回報實際檔案、檢查結果、未執行事項與下一步。接續先讀規則和進度，核對操作狀態再工作。需求變更只更新受影響部分。

## 控制讀取與輸出範圍

- 按需讀參考：建檔讀 setup，資料處理讀 data-management，交接或容量判斷讀 context-strategy；不每輪載入全部參考。
- 同一對話中，已讀且確認未變更的內容沿用。變更狀態不明、對話壓縮後或新對話時，核對必要規則與進度，不假設記憶完整。
- 先依索引找精確路徑，再搜尋相關資料夾、關鍵字及段落。找不到才逐步擴大範圍，不預設掃描全專案。
- 工具先回報檔名、筆數、錯誤與必要差異；不足以判斷時再讀原文。長輸出保存後按問題讀取，不反覆讀完整日誌。
- 每輪只確認新答案；方案確認與交接才整合摘要。只建需要的資料夾，只更新變更部分並核對相關跨檔一致性。
- 不因縮短輸出省略來源限制、必要原文、驗證證據或進行中操作狀態。這些做法不保證總 Token 下降。

## 核心限制

- 不覆寫來源，不猜值、不自動刪重複；依已確認規則另存工作檔，保留證據並重跑檢查。選擇整理方式不等於任意搬檔或刪除授權。
- 未授權搬檔、覆寫、提交、推送或發布，先提供具體方案；已授權例行建檔不重複請求批准。
- 保存不等於壓縮。未知用量不報百分比；進行中操作保存 ID 與狀態，不重啟同一工作。提醒後繼續已授權工作，安全停點才評估交接。
- 規則不改變模型容量、不安裝背景監控，不聲稱執行無法呼叫的斜線指令。
- 效益定位為減少重複交代與重做，不保證總 Token 下降。示範不是實作證據；不得宣稱未執行的品質檢查或備份已完成。
- 中文說明採短句與單一指令原則，不宣稱符合完整 ASD-STE100 英語規範。
