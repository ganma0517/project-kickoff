# 訪談題庫

按 A 至 E 的順序取得答案。這是題庫，不是必問清單。

預設每次只問一題。使用者要求批次時最多三題。跳過已有答案的題目。每個問題只問一件事。

## 開場 類型與預設資料夾

先依已知資訊選一題。沒有目的時先問目的；目的已知後，逐題取得專案類型、名稱與位置。再依類型提出資料夾清單，標明用途與檔案類型。

1. 這是研究、開發，還是教材專案？
2. 專案要叫什麼名字？
3. 專案資料夾要放在哪裡？

下一回合確認建議資料夾是否合適；只補問原有資訊沒有回答的事。Context 節約設定完成後，依已有授權建立資料夾與各資料夾 README。

## A 做什麼？

1. 這個專案要解決什麼問題？
2. 誰會使用成果？
3. 最後要交付什麼？
4. 這次先不做哪些內容？

產出：一句話目的、使用對象、成果清單、本次範圍。

## B 有什麼？

1. 目前有哪些資料或檔案？
2. 這些資料或檔案放在哪裡？
3. 這些資料有哪些使用限制？
4. 還缺哪些必要資料或權限？

若來源不明，再問：「資料從哪裡取得？」若有缺項，再問：「要怎麼取得？」

產出：資料清單、來源與位置、使用限制、尚缺項目。

## C 怎樣算完成？

1. 成果必須有哪些內容或功能？
2. 要用什麼方法檢查成果？
3. 誰會確認成果合格？

「交件」或「上線」不能取代成果檢查。不知道怎麼檢查時，依成果提出建議。

例：報告的分析可以重跑，表格數字與分析結果一致。
例：網頁在手機可使用，篩選結果與原始資料一致。

產出：每項主要成果的合格條件、檢查方法、確認者。

## D 何時做？

1. 何時要交付？
2. 你可以投入多少時間？
3. 有哪些工具或預算限制？

依答案提出工作階段。每階段列出成果與完成條件。先處理會阻礙後續工作的事。

再問：「這個安排是否合適？」多人合作時，再問：「各項工作由誰負責？」

產出：期限、資源、工作階段、第一步、可能阻礙與處理動作。

## E 放在哪裡？

1. 專案資料夾要放在哪裡？
2. 成果要怎麼分享？
3. 哪些內容不能公開？

提出資料夾與版本保存方案。需要 git 時，先說明「git 可保存檔案修改紀錄」。已有 repo 時，沿用現有方式。

再問：「要採用這個存放與版本保存方式嗎？」不要要求新手自行選分支策略。

產出：專案位置、成品位置、分享方式、排除內容、版本保存方式。

## 回答處理

- 已知：整理答案，繼續下一組。
- 不知道：提出一個建議，給出理由。
- 有衝突：指出衝突，只補問受影響的問題。
- 暫時無法回答：記錄待確認事項。記錄最晚確認階段、受影響工作與延後可能增加的往返；阻礙下一步時先確認。

每組只覆述該組結論。最後用一份摘要整合全部答案。

## 建檔前：對話管理補問

從 A 至 E 的答案提出對話管理方案。只問尚未知道的事：

1. 哪些內容需要逐字保留？
2. 哪些工作完成後可以換新對話？
3. 有沒有不能中斷的操作？

仍預設一次一題；只有使用者要求批次才最多三題。記憶模式整體方案可一次確認，不延伸為其他題組的綁題授權。使用者不知道時，依專案提出建議。

產出：保存時機、壓縮時機、保留清單、交接方式。不要要求新手自行決定 token 閾值。
