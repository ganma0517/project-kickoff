# 資料整理與品質規則

初始化或接手專案時讀取本檔，把適用規則寫進配置。日常清理沿用已確認規則，不重跑完整訪談。先盤點與檢查，再決定修正；不為讓程式通過而猜值。

## 先選整理方式

涉及整理需求時，讀已知答案後詢問一次「這次想怎麼整理？」。環境有可用選項問答工具時，用工具呈現；沒有時使用短文字選單。不要宣稱一定能開啟視窗。不重問已明確選定的方式。

提供下列方式，可依需求縮減選項：

1. **只盤點與建索引（建議起點）**：列出檔案位置、來源、版本與缺漏，建立說明；不搬移、不改資料。
2. **分類整理副本**：依用途分類獲准副本，保留原檔；先列來源、目標位置、授權及同名衝突。
3. **檢查並清理資料**：先品質檢查，再依已確認規則另存工作資料，保存修正證據；不自動猜值、去重或補零。
4. **歸檔舊版本**：確認歷史版本、來源索引、目標位置與保存需求；依具體授權處理，不預設可刪除。
5. **不知道，請建議**：依目前資料提出一個起點及理由，讓使用者選擇；無法判斷時先建議只盤點。

選擇方式不等於授權任意搬檔、覆寫或刪除。只補問所選方式必要的缺漏，逐題釐清。將方式、範圍、來源與輸出寫入摘要及 PROGRESS，再依已有授權執行。權限不足或來源限制未知時先做可行的盤點，其他動作留待確認。

## 1. 盤點來源

- 記錄資料位置、來源、取得日期、版本、用途及使用限制。未知就標待確認。
- 依類型區分來源、工作資料、程式、草稿、成果及證據；既有位置與命名先沿用。
- 不因副檔名或檔案日期相近就判定相同。資料主鍵、欄位定義與重複判準需確認。
- 不批次搬移、改名、刪除或公開來源。先提出具體清單，依已有授權及限制處理。
- 受限資料維持獲准位置。索引與日誌不寫個資、憑證或敏感列值。

## 2. 逐題確認檢查條件

只問必要缺漏，一次一題；依用途選用下列項目，不要求使用者填完整表格。

| 資料類型 | 需確認的檢查條件 |
| --- | --- |
| 表格／問卷 | 必要欄位、型態、主鍵、缺值碼、重複定義、單位、日期、合法範圍 |
| 教材／文件 | 來源、授權、適用課程、版本、內容核對與確認者 |
| 圖片／影音 | 來源、授權、格式、可開啟性、版本與個資限制 |
| 程式／成果 | 輸入輸出、執行環境、測試、驗收及可重跑方法 |

尚未確認品質條件時只能回報盤點或初步檢查，不能宣稱資料已合格。

## 3. 先執行檢查，再決定

有資料且授權允許時，以工具執行適用檢查。沒有資料或工具時留下待辦，不編造列數、錯誤或檢查分數。

分開記錄：通過、失敗、未執行、不適用。樣本檢查標明範圍，不能推論全檔已通過。將問題位置與證據記在獲准的持久位置。

- 重複 ID 是待查問題，不等於可刪除；確認它是重送、重複觀測或合法多筆紀錄。
- 缺值不自動補零；先確認缺值碼、分析用途及處理規則。
- 型態轉換、單位、日期、欄位改名、異常值及刪列須有來源或已確認規則。禁止靜默截斷、丟列或強制轉換失敗值為缺值。
- 本教材 A04=30、去除重送及總報名108只適用模擬案例，不套用真實專案。不得為符合預期總數而修改資料。

## 4. 另存工作檔，保留修正證據

修正依已確認規則與授權執行。保留來源原檔，工作輸出另存至確認位置，不覆寫已存在版本而不核對。實際程式或工具步驟應可重跑。

每個變更記錄：來源版本、問題、規則及依據、實際動作、受影響筆數、輸出位置、執行時間與檢查結果。未確定筆數就標未知；日誌只留必要、非敏感資訊。

修正後重跑檢查。核對列數、主鍵、缺值與彙總是否符合已確認條件，說明合法的差異。仍失敗就保留問題，不標記完成。

## 5. 歸檔、更新與接續

- 更新 README 的目前資料及成果索引；記錄來源到工作檔、程式、成果與證據的對應。
- 更新 PROGRESS 的真實結果、未解問題與下一步。檢查未完成就清楚標示。
- 原始、工作與交付版本採一致命名；日期或版本號依既有約定，不自行宣稱某檔「最新」。
- 新資料到來，先確認欄位與規則是否改變，再檢查、處理、驗證及更新索引；不盲用上次品質結論。
- 歸檔需保留來源與證據對照；備份需另執行及驗證還原。重要證據先移至持久位置，再依授權清理暫存。
- 主對話只留結論、檢查狀態與必要路徑。精確定義與證據保存在來源，不以摘要替代。
